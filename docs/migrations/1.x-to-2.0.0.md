# Migración de 1.x a 2.0.0

`2.0.0` corrige contratos que estaban documentados pero no implementados. Es un release incompatible: si dependías del comportamiento anterior, revisa esta guía antes de actualizar.

## Resumen de cambios incompatibles

| Área | 1.x | 2.0.0 |
|---|---|---|
| Gating | `registry.gates` podía anunciar tools fuera de `config.tools` | `config.tools` es la autoridad; el registry se filtra por estado, `gates` y `condition` |
| Vercel | `inject().tools` era mutable y solo del estado actual; `prepareStep` no funcionaba con `ai@4` | `inject().tools` es el `ToolSet` completo; `prepareStep` devuelve `activeTools`; requiere AI SDK 7 |
| Async | Una transición lenta podía sobrescribir el estado | Una transición obsoleta lanza un error |
| Tipos | `createFSM<const S>` devolvía `FSMInstance` con `transitionTo(string)` | `createFSM` devuelve `FSMPublic<S>`; `transitionTo` acepta solo la unión literal |
| Node | `>=18` | `>=20` |
| Peers | Cinco peers de proveedores | Sin peers ni dependencias de runtime |
| Budget | Contador con `onLoop` repetido y `repeated` ambiguo | `onLoop` una vez por episodio; `repeated` exige nombre; reset en transición |

## 1. `config.tools` es la autoridad

Antes, una tool podía anunciarse si estaba en `registry.gates`, aunque no estuviera en `config.tools`. Ahora debe estar en **ambos** para el estado actual.

```ts
const fsm = createFSM({
  initialState: 'B',
  states: ['A', 'B'] as const,
  tools: {
    A: [],
    B: ['charge'], // obligatorio para que charge se active en B
  },
})

const registry: ToolEntry<Ctx>[] = [
  {
    name: 'charge',
    gates: ['B'], // además debe incluir el estado actual
    build: () => ({ /* ... */ }),
  },
]
```

Si una tool estaba solo en el registry, agrégala a `config.tools` para el estado correspondiente o deja de usarla.

## 2. Adaptador de Vercel

El adaptador ahora construye un `ToolSet` estable y usa `activeTools` en `prepareStep`. Ya no muta el objeto `tools`.

**Antes (1.x):**

```ts
const adapter = createVercelAdapter(fsm, registry, context)
const { tools, prepareStep } = adapter.inject()
// tools solo contenía las tools del estado actual
```

**Ahora (2.0.0):**

```ts
import { generateText, isStepCount } from 'ai'
import { createVercelAdapter } from 'reactive-fsm/adapters/vercel-ai'

const adapter = createVercelAdapter(fsm, registry, context)

const result = await generateText({
  model,
  prompt,
  ...adapter.inject(), // tools + prepareStep
  stopWhen: isStepCount(5),
})
```

- `inject().tools` contiene todo el registry. No lo uses para saber qué está activo; usa `prepareStep` o el estado del FSM.
- `prepareStep` devuelve `{ activeTools: [...] }` o `{ toolChoice: 'none' }`.
- Cada tool de `build()` debe ser una tool de AI SDK 7: `inputSchema` y `execute`.
- El adaptador requiere AI SDK 7. No hay compatibilidad con `ai@4`.

## 3. Transiciones async obsoletas

Si el estado cambia mientras un guard async está pendiente, `transitionToAsync` ahora rechaza:

```ts
try {
  await fsm.transitionToAsync('PAYMENT')
} catch (error) {
  // El estado cambió mientras se validaba el guard.
  // Reintenta desde el estado actual o cancela la operación.
}
```

No asumas last-write-wins. Si necesitas serializar, hazlo en tu aplicación; la librería usa una revisión monotónica y no una cola.

## 4. Tipos literales

Usa `as const` en `states` para conservar la unión:

```ts
const fsm = createFSM({
  initialState: 'A',
  states: ['A', 'B'] as const,
  tools: { A: [], B: [] },
})

fsm.transitionTo('B') // OK
fsm.transitionTo('TYPO') // error de compilación
```

`createFSM` devuelve `FSMPublic<S>`; los métodos internos `_registerToolCall`, `_setState`, etc. ya no forman parte del tipo público. Si los usabas, migra a la API pública o mantén una instancia interna separada.

## 5. Tool budget

El budget sigue siendo un presupuesto de admisión **entre pasos**:

- `onLoop` se dispara una vez por episodio, no en cada llamada posterior.
- `mode: 'repeated'` requiere `toolName`; sin nombre lanza un error.
- `maxConsecutiveTools` debe ser positivo.
- El contador se resetea al cambiar de estado.
- Varias tool calls dentro de un mismo paso pueden superar el presupuesto antes de la próxima comprobación. No es un límite estricto por llamada.

Si necesitas un límite estricto, valida en el `execute` de tus tools o en tu capa de ejecución.

## 6. Node y peers

- Node 20+.
- No hay `peerDependencies`. Si usas el adaptador de Vercel, instala `ai@7` tú mismo.
- El paquete no importa `ai` en runtime; los tipos del adaptador son estructurales.

## 7. Adaptadores experimentales

Solo el adaptador de Vercel tiene test de contrato de runtime en 2.0.0. OpenAI, Anthropic, LangChain y Gemini siguen disponibles, pero son experimentales y no se ejecutaron contra APIs reales. No los uses como base de una integración crítica sin añadir tus propios tests.

## Checklist de migración

- [ ] Actualizar a `reactive-fsm@2.0.0` y Node 20+.
- [ ] Añadir a `config.tools` toda tool que deba anunciarse en cada estado.
- [ ] Revisar que `registry.gates` incluya el estado actual.
- [ ] Migrar el adaptador de Vercel a AI SDK 7 y `stopWhen`.
- [ ] Manejar el rechazo de transiciones async obsoletas.
- [ ] Añadir `as const` a `states` si quieres tipos literales.
- [ ] Revisar `onLoop`/`repeated` si usabas el budget.
- [ ] Ejecutar `pnpm build`, `pnpm test`, `pnpm typecheck` y `npm pack` en tu proyecto.

## Rollback

Si no puedes migrar todavía, fija `reactive-fsm@1.4.1`. Es la última versión con el contrato anterior.

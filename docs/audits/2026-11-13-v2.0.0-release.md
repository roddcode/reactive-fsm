## Cambios incluidos

- `config.tools` es la autoridad del gating; el adaptador de Vercel cruza `config.tools`, `registry.gates`, `condition` y estado actual.
- Adaptador de Vercel para AI SDK 7: `ToolSet` estable, `prepareStep` devuelve `activeTools`, sin mutación.
- Test real con `generateText` + `MockLanguageModelV3` que cruza IDENTITY → BOOKING y activa la tool de B.
- Transiciones async obsoletas rechazadas con revisión monotónica; cubre A → B → A.
- Tool budget explícito: `onLoop` una vez por episodio, `repeated` exige nombre, threshold positivo, reset por transición, multi-call step contado una vez.
- Tipos literales: `FSMPublic<S>`, `createFSM` devuelve la interfaz pública, `transitionTo(state: S)`.
- Sin `peerDependencies` ni dependencias de runtime; `ai`/`zod` solo en `devDependencies`.
- Node 20+.
- Guía de migración `docs/migrations/1.x-to-2.0.0.md`.

## Riesgos residuales

- El tool budget es admisión entre pasos; varias tool calls del mismo paso pueden superarlo. Documentado.
- Solo Vercel tiene test de runtime; OpenAI, Anthropic, LangChain y Gemini son experimentales.
- No se ejecutaron APIs reales de proveedores; se usó `MockLanguageModelV3`.
- `streamText` no está cubierto por el test de integración.
- El adaptador de Vercel construye el `ToolSet` completo; `build()` debe ser una fábrica pura.
- La eliminación de adaptadores no soportados y APIs muertas queda para 2.1.0/3.0.0 según ADR-0002.
- `npm publish` requiere reautenticar el token; el `.npmrc` local está inválido.
